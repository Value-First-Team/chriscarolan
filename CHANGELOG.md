**Who owns this site.** No seat owns its practice yet: the registry (`architecture.json`) records `agent_owner: null`, `owner_status: "pending-hire"`, human owner Chris Carolan. Showcase owns the code and keeps this file as the code owner. `rostrum.md`'s description names this site: Rostrum "owns the host relationship and the personal brand's PR seat (chriscarolan.com, Brand Alchemy, the PR tab)". That is stated here and not resolved here; which seat owns the site's practice is the registry's to record.

This repo has no version number. The live site is the Next.js app in `next/`. The `package.json` at the repo root belonged to the retired Astro build; it carried `0.1.0` and nothing read it, so that field was dropped on 2026-09-28 in the commit that adopted this file (the root lockfile was `pnpm-lock.yaml`, which records no project version), and the whole retired Astro build left the repo root later that day (`51fef89`). `next/package.json` still says `0.1.0`, and the checker never reads it. `L4-orchestration/scripts/repo-changelog-lint.mjs` therefore runs this file in no-version mode.

**An entry is a production deploy that changes what a visitor sees or can do** on chriscarolan.com, including what a search engine or other reader of the page's data sees: a copy change a person would notice, a section added or removed, a broken thing fixed, a layout or theme change, a redirect added or moved. The site is one page. It is headed `## <date> — deploy <sha>`, where the sha is the commit that carries the change and the date is the UTC date of its production deploy. Production is the Vercel project `chriscarolan`, which builds `next/` from `main`; it serves that commit or a later one. Newest at the bottom. The reader here is a visitor, so **Consumer action** says what a visitor has to do: usually nothing. **Owner** is the seat that built the change.

**A shared-package pin move gets an entry too.** The page is drawn by the shared `@vf` packages, so moving a pin is how their changes reach visitors. Say what a visitor now sees differently; if the move changes nothing a visitor would notice, say that in one line.

**What the check enforces.** Run `npm run check` in `next/` before you push. It runs `npm run assert:changelog` first, then the typecheck. `assert:changelog` runs `repo-changelog-lint.mjs` through `repo-changelog-lint-run.mjs` at the repo root, a launcher generated by `--print-runner`. Regenerate it; never hand-edit it. The check fails in three cases:
- this file is missing;
- any entry lacks one of the four fields;
- a commit after the newest entry's cited commit (and after `294fed2`, where this check was adopted) touches `next/src`, `next/public`, `next/next.config.ts`, `next/vercel.json`, `next/tailwind.config.ts`, `next/postcss.config.cjs` or `next/package-lock.json` with no newer entry.

`next/package.json` is not on that list, so editing a script there does not demand an entry; a dependency change moves `next/package-lock.json`, which is on it. The retired Astro build that used to sit at the repo root was deleted on 2026-09-28 (`51fef89`); `next/` is the only tree. The check sees commits only, never uncommitted edits: commit the change, add its entry citing that commit, then push. A push made from a Claude Code session on the MainBrain station runs the same check (`.claude/hooks/repo-changelog-push-gate.mjs`) and is refused when it fails. It is not part of the Vercel build. Outside a MainBrain checkout the launcher prints SKIPPED and checks nothing; set `MAINBRAIN_ROOT` to a real MainBrain checkout to run it from anywhere else.

**The record starts at adoption.** The first entry is the most recent production deploy a visitor would notice, as of adoption on 2026-09-28. Two production deploys since that one changed nothing anyone sees and have no entry: `4145aa3` (the shell config reads the constellation registry instead of a local copy; its commit records the footer text identical before and after) and `294fed2` (README only), which is what production serves at adoption.
